# AzurLaneAutoScript macOS 迁移计划

## 最终目标

在 macOS 上稳定运行 Alas 的核心自动化链路：

```text
真实截图 -> 图像识别/OCR -> 页面判断 -> 决策 -> 点击/滑动 -> 任务推进 -> 调度恢复
```

迁移验证以手动 ADB 连接为输入前提。用户提供设备地址或 serial，macOS 侧通过 ADB 获取游戏画面。

## 迁移主线

迁移工作从真实游戏截图验证视觉层开始，而不是从 WebUI、Electron 或模拟器自动管理开始。

验证顺序为：

```text
ADB 连接 -> 获取真实截图 -> 归一化截图输入 -> OpenCV 图像识别 -> OCR -> 样本与基准 -> 控制闭环 -> 最小真实任务 -> 调度器/WebUI -> 安装与发行
```

WebUI、Electron、模拟器自动发现和模拟器自动启动属于后续集成与体验层，不作为第一验证入口。

## 阶段计划

### 1. 以手动 ADB 连接作为输入前提

目标：用户手动提供设备地址或 serial，macOS 侧能够通过 ADB 访问目标设备。

验证方式：确认配置中的 ADB 地址可用于后续截图命令或项目截图链路。

详细设计：[step-1-manual-adb.md](step-1-manual-adb.md)

### 2. 获取真实游戏截图

目标：从真实设备或模拟器获取当前游戏画面，并保存为原始截图文件。

验证方式：确认截图文件存在、非空、可打开，并且人工确认内容是当前游戏画面。

详细设计：[step-2-capture-real-screenshot.md](step-2-capture-real-screenshot.md)

### 3. 归一化截图输入

目标：把原始真实截图转换为 Alas 视觉层可消费的标准图像输入。

验证方式：确认图像可被 OpenCV 读取，尺寸、方向、颜色通道和画面区域符合视觉层预期。

详细设计：[step-3-normalize-screenshot-input.md](step-3-normalize-screenshot-input.md)

### 4. 验证 OpenCV 图像识别

目标：在真实截图上运行按钮、页面、模板、地图等识别逻辑。

验证方式：记录识别结果、置信度和耗时，确认关键页面与关键模板识别稳定。

### 5. 迁移并验证 OCR

目标：使用 macOS 可用的 OCR 后端识别数字、时间和文本。

验证方式：在真实截图上验证 OCR 输出，重点检查金币、石油、次数、价格、倒计时等关键字段。

### 6. 建立截图样本和识别基准

目标：把真实截图沉淀为可重复运行的测试样本。

验证方式：保存截图、场景说明和期望识别结果，用于 Windows/macOS 对比和后续回归测试。

### 7. 验证控制闭环

目标：识别成功后执行点击、滑动等基础操作。

验证方式：每次操作后重新截图，确认页面状态按预期变化。

### 8. 运行最小真实任务

目标：验证识别、决策和控制可以串联成真实任务流程。

验证方式：优先运行 `GotoMain`、`Restart` 或简单收取类任务，检查任务日志、关键截图和结束状态。

### 9. 验证调度器和 WebUI

目标：确认核心自动化闭环可以接入项目调度与配置管理。

验证方式：验证任务调度、长期运行、配置编辑、日志显示和进程管理可用。

### 10. 完善安装与发行

目标：让普通 macOS 用户可以安装和运行。

验证方式：锁定依赖，补充安装文档，配置 CI，处理 Electron `.app` 打包、签名和公证。
