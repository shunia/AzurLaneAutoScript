# 第 2 步：获取真实游戏截图

## 目标

确认 macOS 可以通过第 1 步验证过的 ADB serial/address 获取一张真实游戏截图文件。

本阶段只验证“能拿到真实截图文件”，不验证截图尺寸、方向、颜色通道、OpenCV、OCR、点击控制、任务执行或 WebUI。

## 输入

- 第 1 步验证通过的 ADB serial/address
- 目标设备或模拟器上已打开碧蓝航线
- 游戏画面处于可见状态

## 输出

一张原始截图文件，例如：

```text
raw_screenshot.png
```

该文件将作为第 3 步“归一化截图输入”的输入。

## 实施范围

本阶段可以使用最小 ADB 截图命令获取截图，也可以调用项目现有截图链路获取截图。

如果项目截图链路在 macOS 上尚不可用，允许先使用 ADB 命令生成原始截图文件。该路径只作为截图获取验证入口，不代表最终自动化运行时的截图方案。

## 执行步骤

1. 确认第 1 步的 `<serial>` 仍可通过 ADB 访问。
2. 确认游戏客户端处于前台可见状态。
3. 执行截图命令并保存原始截图文件。
4. 确认截图文件存在且非空。
5. 人工打开截图文件，确认内容是当前游戏画面。
6. 记录截图来源和保存路径。

## 验证方式

执行：

```bash
adb -s <serial> exec-out screencap -p > raw_screenshot.png
```

通过标准：

- `raw_screenshot.png` 存在。
- 文件大小大于 0。
- 图片文件可以被系统图片查看器打开。
- 人工确认图片内容是当前碧蓝航线游戏画面。
- 图片不是黑屏、锁屏、桌面、模拟器外壳或损坏图像。

## 记录信息

验证通过后记录以下信息：

- ADB serial/address
- 截图命令或截图方式
- 原始截图路径
- 文件大小
- 游戏所在页面或场景
- 截图时间

## 退出条件

至少保存一张有效的真实游戏原始截图后，进入第 3 步“归一化截图输入”。

## 失败处理

- 文件不存在或大小为 0：检查 ADB 连接和截图命令是否执行成功。
- 图片无法打开：检查输出重定向和 PNG 数据是否损坏。
- 图片为黑屏：检查设备是否锁屏、游戏是否在前台、模拟器画面是否可见。
- 图片不是游戏画面：切回游戏客户端后重新截图。
- `adb exec-out` 不可用：记录失败原因，可尝试等价的 ADB 截图方式，但仍只输出原始截图文件。

## 非目标

- 不判断截图是否为 `1280x720`。
- 不判断横竖屏方向。
- 不判断 RGB/BGR 通道。
- 不读取 OpenCV/Numpy 数组。
- 不验证 OpenCV 模板匹配。
- 不验证 OCR。
- 不执行点击或滑动。
- 不运行 Alas 任务。
