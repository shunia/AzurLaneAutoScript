# 第 3 步：归一化截图输入

## 目标

把第 2 步得到的原始真实截图转换为 Alas 视觉层可消费的标准图像输入。

本阶段只验证截图输入格式和图像质量，不验证 OpenCV 模板匹配结果、OCR 结果、点击控制、任务执行或 WebUI。

## 输入

第 2 步输出的原始截图文件，例如：

```text
raw_screenshot.png
```

## 输出

- 一张归一化后的标准截图文件，例如 `normalized_screenshot.png`
- 一份截图元数据记录

归一化后的截图将作为第 4 步“验证 OpenCV 图像识别”的输入。

## 实施范围

本阶段确认原始截图能被 Python/OpenCV 正常读取，并检查是否符合 Alas 视觉层对图像输入的基本预期。

如发现截图存在方向、分辨率、黑边、缩放或颜色通道问题，本阶段只记录问题并决定是否可以归一化为标准输入；无法稳定归一化时，不进入第 4 步。

## 标准输入要求

归一化后的图像应满足：

- 可被 OpenCV 读取为非空图像。
- 图像具有 3 个颜色通道。
- 宽高语义符合 `1280x720` 横屏游戏画面。
- 画面方向正确。
- 颜色通道语义明确。
- 游戏画面区域没有明显黑边、裁切或异常缩放。

## 执行步骤

1. 使用 Python/OpenCV 读取原始截图。
2. 检查图像是否为空。
3. 记录图像 shape、宽高、通道数。
4. 检查画面方向是否为横屏游戏画面。
5. 检查颜色通道语义，明确后续视觉层使用 BGR 或 RGB。
6. 检查是否存在黑边、裁切、缩放或异常空白区域。
7. 如需要且规则明确，生成归一化截图。
8. 保存归一化截图和元数据。

## 验证方式

最小 OpenCV 读取验证：

```python
import cv2

image = cv2.imread("raw_screenshot.png")
assert image is not None
print(image.shape)
```

通过标准：

- `image is not None`
- `image.shape` 可解释为三通道图像
- 归一化后图像为 `720x1280x3`
- 人工确认归一化截图方向正确、画面清晰、内容仍为游戏画面

## 记录信息

验证通过后记录以下信息：

- 原始截图路径
- 归一化截图路径
- 原始图像 shape
- 归一化图像 shape
- 颜色通道假设
- 是否旋转
- 是否裁切
- 是否 resize
- 是否发现黑边或缩放
- 归一化规则说明

## 退出条件

至少一张真实截图被转换成符合视觉层预期的标准输入后，进入第 4 步“验证 OpenCV 图像识别”。

## 失败处理

- OpenCV 无法读取：检查截图文件是否损坏，返回第 2 步重新截图。
- 图像不是三通道：记录格式问题，确认是否需要转换颜色模式。
- 尺寸不是 `1280x720`：记录原始尺寸，判断是否为设备分辨率或缩放设置问题。
- 方向错误：记录 orientation 问题，后续决定是否复用项目旋转处理。
- 出现黑边、裁切或缩放：记录实际游戏画面区域，不进入 OpenCV 识别验证。
- 颜色异常：保存原图和读取图，明确 RGB/BGR 转换关系。

## 非目标

- 不验证按钮、页面、模板或地图识别结果。
- 不验证 OCR。
- 不执行点击或滑动。
- 不运行 Alas 任务。
- 不启动 WebUI。
- 不设计截图方法自动 benchmark。
